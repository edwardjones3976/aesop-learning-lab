## Principal objective selected before implementation

Deliver **transparent, evidence-based path selection and delayed outcome inspection** in the existing five-concept local preview. The service will derive per-kind scored counts, independent versus assisted results, and a specifically labeled delayed held-out outcome from immutable attempts. It will recommend a due check first, then an unfinished lesson, then practice, with a visible reason and learner override through the existing concept controls. Empty evidence will remain `insufficient_evidence`; no mastery or causal claim will be made. An isolated clock-controlled journey will verify the path from lesson through delayed outcome and export/delete.

Candidate scoring uses the directive's 30/25/20/15/10 weights, with ordinal 1–5 ratings; weighted values are prioritization aids, not predicted outcomes.

## Implemented and evaluated

The new pure evidence summarizer reads versioned activities and immutable attempts. It returns per-kind observed counts, assisted versus independent candidate-key matches, delayed held-out observations, and a missing-evidence state. It marks familiarity `not_verified` until exposure logging exists. The preview API uses those summaries to select a transparent concept path, and the browser displays both the reason and the evidence while retaining manual concept choice. The service clock is injectable for tests; real learner times are never rewritten.

The isolated journey test covers lesson completion, a saved first answer, a viewed hint, an assisted match that does **not** unlock a check, an independent match, a due check after a simulated day, outcome inspection, export, and deletion. This verifies software behavior only. The study has no human outcome data, no released keys, and no evidence of improved retention or transfer.

Verification on the changed candidate: `PYTHONPATH=src; py -m unittest discover -s tests -q` passed 104 tests; `npm test` in `web` passed 16; `node --check foreman_web/app.js` and `git diff --check` passed. A live loopback API returned five concepts, a lesson recommendation, and `insufficient_evidence`; headless Edge at desktop and mobile widths rendered the recommendation and evidence without console errors or horizontal overflow.
