Method and step results

scripts/pilot_readiness_dry_run.py drives the actual Preview API against a fresh temporary SQLite database and reopens it to simulate a restart. Its clock starts at 2026-10-21 12:00 UTC. Four lessons finish at day 0; the fifth finishes at day 0.25. Visits occur at days 1.001, 2.001, 6.999, 7.001, 14.001 and 14.251, so every started concept's window has closed before final export. Candidate keys supply deterministic synthetic answers; this is never advice to coach a learner. A separate fresh database serves real HTTP and Chromium checks. Temporary databases, downloads and overview files are removed by the helpers.

OWNER-ONLY means the human action was not simulated as consent or an owner decision; the associated software claims were checked as described. Gaps

  1. BLOCKER — Consent is procedural only (G1). Browser boot opens a lesson, creating identity, assignment and exposure before any in-app confirmation. The runbook's consent-first owner workaround is accurate, but this is not ready for an unattended real learner. Ratified step 8 supplies the gate and consent wording; step 9 remains the owner's go/no-go.
  2. SHOULD-FIX — Setup/return blocks can continue in the wrong directory (G2). Reproduced for runbook steps 3 and 4 under PowerShell's default nonterminating error behavior. Validate native exit codes, make directory changes terminate on failure, and verify the resolved worktree directory before starting. A matching clean SHA alone cannot distinguish two worktrees containing different learner databases. No ratified step explicitly fixes these command guards. Fix and recheck them before using these commands for a real learner.
  3. BLOCKER — Owner key-review/reporting policy decision remains outside this dry run (G3). Software correctly returns provisional and insufficient_evidence; it does not supply the owner's written decision on qualified review versus permanent provisional reporting. Ratified step 11 supplies that decision and is an explicit prerequisite for step 9. This is a governance dependency, not a classifier failure or a claim that an external owner decision was exhaustively searched for.
  4. NOTE — Some delay reporting requires raw-record arithmetic (G4). contaminated observations omit elapsedDays/elapsedSeconds in the primary derived observation. The raw export makes the runbook's actual-delay report possible, but the owner must join the first attempt to its lesson completion. No ratified step explicitly fixes this presentation gap.
  5. NOTE — Early checks are defensive classifier coverage (G5). The normal scheduler prevents early week responses; this dry run covered early with an in-memory v8 fixture rather than an impossible normal-path session. No ratified fix required. Browser clearing, consent, comprehensive privacy assurance and owner reporting remain outside automated software validation.
